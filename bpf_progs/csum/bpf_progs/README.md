# XDP BPF Helper Performance Test

This program tests the performance difference between the original `bpf_csum_diff` helper and the optimized `bpf_csum_diff_optimized` helper.

## Overview

The XDP program:
- Attaches to a network interface (typically `lo` for testing)
- Calls both `bpf_csum_diff` and `bpf_csum_diff_optimized` with identical 20-byte buffers
- Measures execution time for each helper using `bpf_ktime_get_ns()`
- Verifies both helpers return identical results
- Prints detailed timing data to the trace pipe
- Logs helper invocations to kernel dmesg

## Building

```bash
make
```

This will generate:
- `bpf_prog.o` - The compiled XDP BPF program
- `loader` - User-space program to load and attach the XDP program
- `trigger` - Program to send test packets

## Running

### Quick Start (Automated)

Run the automated test script:
```bash
sudo ./run.sh
```

This will:
1. Build the programs
2. Clear trace buffer and dmesg
3. Start trace capture in background
4. Load and attach XDP program to `lo` interface
5. Send 100 test packets
6. Save results to `trace_output.txt` and `dmesg_output.txt`

### Manual Steps

#### 1. Load the XDP program

Attach to loopback interface:
```bash
sudo ./loader bpf_prog.o lo
```

The program will print:
```
XDP csum test program attached to lo successfully!
Program will run on every packet received on lo.
Monitor output: sudo cat /sys/kernel/debug/tracing/trace_pipe
Press Ctrl+C to exit
```

#### 2. Monitor trace output (in another terminal)

```bash
sudo cat /sys/kernel/debug/tracing/trace_pipe
```

#### 3. Trigger test packets

In a third terminal:
```bash
./trigger 100
```

This sends 100 UDP packets to localhost, triggering the XDP program.

## Expected Output

### Trace Output (trace_output.txt)

You should see detailed trace output like:
```
trigger-322     [002] ..s21   910.937874: bpf_trace_printk: === XDP program triggered ===
trigger-322     [002] ..s21   910.937874: bpf_trace_printk: Calling original bpf_csum_diff
trigger-322     [002] ..s21   910.937874: bpf_trace_printk: Original result: 0xc8c8, time: 230 ns
trigger-322     [002] ..s21   910.937874: bpf_trace_printk: Calling optimized bpf_csum_diff_optimized
trigger-322     [002] ..s21   910.937874: bpf_trace_printk: Optimized result: 0xc8c8, time: 27 ns
trigger-322     [002] ..s21   910.937874: bpf_trace_printk: DATA: original=230 optimized=27
```

Where:
- `original` = time in nanoseconds for `bpf_csum_diff`
- `optimized` = time in nanoseconds for `bpf_csum_diff_optimized`
- Results (0xc8c8) should be identical for both helpers

### Kernel Messages (dmesg_output.txt)

The optimized helper logs to dmesg:
```
[  910.937874] bpf_csum_diff_optimized called: from_size=20, to_size=20, seed=0x0
```

## Test Scenario

The program tests a common use case:
- **20-byte buffers** (typical IP header size)
- **Diff operation** (comparing two buffers with seed=0)
- **Test data**: Fixed buffer patterns for reproducible results
- This matches the IP header checksum update scenario

## Analyzing Results

Run the analysis script:
```bash
./analyze_speedup.sh
```

This will:
- Parse `trace_output.txt` for all DATA entries
- Calculate statistics (average, median, min/max, standard deviation)
- Compute speedup ratio
- Display comprehensive performance comparison

## Troubleshooting

### Empty trace output
- Make sure you ran `run.sh` as root
- Check that the XDP program is attached: `ip link show lo`
- Verify BPF tracing is enabled: `cat /sys/kernel/debug/tracing/tracing_on`

### No packets triggering XDP
- The trigger sends packets to `127.0.0.1:9999`
- Make sure no firewall is blocking loopback traffic
- Try manually: `ping -c 1 127.0.0.1`

### Compilation errors
- Ensure you have `clang`, `llvm`, and kernel headers installed
- Make sure `vmlinux.h` is generated: `make` should create it automatically
- Verify libbpf is available: `ldconfig -p | grep libbpf`
